# Corrupted Activity Repair

These maintenance tools are for the single runaway manual workout described on 2026-06-22. They are not migrations and must not be added to the normal Supabase migration workflow.

## Why The Corruption Spread

The affected client allowed a manual duration to reach the save path without a realistic upper bound. Activity EXP scales with duration, the database accepted any positive `duration_seconds`, and the original `process_activity_rewards` function trusted the client-populated `exp_earned` and `stat_exp` fields. The oversized reward then changed character EXP, coins, stat EXP, mission completion, personal records, achievements, level-up celebrations, evolution presentation, and skill-point state.

Deleting only the activity would leave those already-applied side effects in place. The repair therefore reverses the recorded transaction and reconstructs derived state from the remaining activities.

## Files

- Read-only audit: `supabase/maintenance/20260622_audit_corrupted_gym_activity.sql`
- Targeted repair: `supabase/maintenance/20260622_repair_corrupted_gym_activity.sql`

## 1. Run And Review The Audit

1. Open the Supabase Dashboard for the LevelUp Fitness project.
2. Open **SQL Editor** and create a new query.
3. Paste the complete audit file and run it.
4. Find the row matching the runaway Gym workout. Confirm the type, title, timestamps, approximately 11,414-hour duration, and unusually large reward.
5. Copy these two values from that row:
   - `candidate_user_id`
   - `candidate_activity_id`
6. Export or screenshot the complete result before doing anything else. In particular, retain the activity, character, mission, achievement, record, celebration, presentation, and skill-progress JSON.

Do not run the repair until the audit result has been reviewed and exactly one suspicious activity belongs to the affected user. The repair deliberately aborts if the user has more than one suspicious candidate.

## 2. Prepare A Dry Run

1. Open `supabase/maintenance/20260622_repair_corrupted_gym_activity.sql` locally.
2. Replace the first UUID placeholder with the reviewed user ID.
3. Replace the second UUID placeholder with the reviewed activity ID.
4. Leave `apply_changes` set to `false`.
5. Leave the final statement as `ROLLBACK`.
6. Paste the complete script into a new Supabase SQL Editor query and run it.

The dry run validates ownership, suspicious values, character ownership, and reward-ledger availability. It prints the BEFORE snapshot and deterministic mission, record, and streak reconstructions. It makes no persistent changes.

## 3. Review The Proposed Result

Compare the dry-run output with account history. The previously visible Level 5 and 271 coins are useful sanity checks, not authoritative repair inputs. The script does not hard-code them.

Review:

- corrected total EXP and formula-derived level;
- each corrected stat EXP value;
- corrected coins;
- invalid mission completions and unlocks to remove;
- rebuilt personal records and streaks;
- achievements that no longer meet their conditions;
- level-up celebrations above the corrected level;
- high-level skill nodes and progression cosmetics attributable to the corrupted event.

Stop if any calculated value is negative, if more than one suspicious activity exists, or if the proposed state does not match valid historical activities.

## 4. Apply The Repair

Only after reviewing the dry run:

1. Change `apply_changes` from `false` to `true`.
2. Replace the final `ROLLBACK` statement with `COMMIT`.
3. Run the complete script once in Supabase SQL Editor.
4. Save the final AFTER result.

The script runs in one transaction. Any failed safety assertion rolls back every change. Running it again cannot subtract rewards twice because the targeted corrupt activity no longer exists; the script stops before mutation.

## 5. Verify The Account

After a successful commit:

1. Run the read-only audit again. The target activity should no longer appear.
2. Verify the character’s level, total EXP, coins, and four stat EXP totals in the final repair output.
3. Verify no negative values exist.
4. Verify valid activities, purchased cosmetics, equipped cosmetics, and unrelated mission rewards remain.
5. Verify personal records point only to remaining activities.
6. Verify only level-up celebrations above the corrected level and generated by the corrupt transaction were removed.
7. Restart LevelUp Fitness, sign into the same account, and confirm the Character, Me, Missions, Achievements, Wardrobe, and Shop views load normally.

## Rollback And Recovery

The default script ends with `ROLLBACK`, which is the safest test mode. Before committing, inspect all result sets in the same SQL run. If anything is wrong, retain `ROLLBACK`; no persistent data changes will occur.

After a `COMMIT`, Supabase SQL Editor cannot automatically undo the transaction. Restore from a database backup or use the saved BEFORE snapshot to prepare a separately reviewed compensating script. Do not guess values or rerun the corrupted reward process.

## Reconstruction Limits

The activity’s real duration is not recorded anywhere independently, so the invalid activity itself cannot be corrected exactly and is removed. Core EXP, stat EXP, mission rewards, gold, and achievement rewards are reversed from the activity’s persisted `reward_summary`, which is the most exact available ledger.

Personal records, mission progress, streaks, character level, evolution stage, and skill points are deterministically reconstructed from remaining valid database rows and the app’s current formulas. GPS split records are rebuilt from saved route timestamps and route distances. Shop purchases remain untouched because there is no complete historical price ledger and they are unrelated to the corrupted workout.
